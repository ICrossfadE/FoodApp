# Food app · інтерфейс v0.2

Next.js-проєкт ресторану доставки їжі. Поточний результат — адаптивні макети без бізнес-логіки. Усі товари, користувачі, замовлення й суми демонстраційні.

## Запуск

Потрібні Node.js 24.x і npm. Із папки проєкту:

```powershell
npm ci
npm run dev
```

Магазин: http://127.0.0.1:3000/; адмінпанель: http://127.0.0.1:3000/admin. Зупинка — `Ctrl+C` у терміналі.

Для перегляду мокапів не потрібні `.env`, база, OAuth чи зовнішні сервіси. Адмінпанель доступна відкрито виключно для перегляду демонстраційних макетів; захист ще не реалізований.

## Що працює зараз

- Переходи між сторінками, розкриття мобільної навігації.
- Перегляд категорій меню через URL і статичних станів через `?state=…`.
- Введення у поля для оцінки зручності компонування; введене не зберігається.

Кошик, збереження форм, Google-вхід, завантаження файлів, пошук, фільтрація адмінських даних, зміна статусів та оформлення **не підключені**. Кнопки дій вимкнені. Екран успіху відкривається окремим посиланням для перегляду й не означає створення замовлення.

Застосовано палітру cream/forest/terracotta, оригінальний SVG-логотип, Tabler Icons і GSAP-анімації. Підтвердження видалення та скасування відкриваються в діалогах із клавіатурною навігацією. Підтримано reduced-motion.

## Перевірки

```powershell
npm run typecheck
npm run lint
npm run build
```

Усі три: `npm run check`.

Перевірка мокапів у headless-браузері, зокрема переповнення на 360/390/768/1440 px, посилань, клавіатурної навігації та WCAG-аудиту основних екранів:

```powershell
npm run build
npm run start
```

В іншому терміналі:

```powershell
npm run qa:mockups
npm run qa:interactions
```

За замовчуванням використовується встановлений Microsoft Edge. Альтернатива:

```powershell
npx playwright install chromium
$env:PLAYWRIGHT_CHANNEL = "chromium"
npm run qa:mockups
```

`MOCKUP_BASE_URL` дозволяє перевірити інший локальний порт. Звіт і знімки зберігаються в `artifacts/mockups/` (не входять до Git). Автоматична перевірка доповнює ручний перегляд та не замінює погодження користувача.

## Структура

- `src/app/(store)` — клієнтські маршрути.
- `src/app/admin` — демонстраційні адміністративні маршрути.
- `src/components/*-views.tsx` — вміст екранів, без API та бізнес-логіки.
- `src/components/ui/button.tsx` — базова кнопка shadcn/ui.
- `src/lib/mock-data.ts` — явно демонстраційні приклади, не контракт API.
- `scripts/page-manifest.ts` — карта сторінок та станів для автоматичних QA-перевірок.
- `docs/MOCKUP_REVIEW.md` — перелік груп і журнал погодження.
- `docs/FRONTEND_SETUP.md` — вибір версій і межі поточного етапу.

Продуктові вимоги: [PRODUCT_PLAN](docs/PRODUCT_PLAN.md), задачі: [TASKS](docs/TASKS.md). Цей фронтенд-етап виконує агент без навчальних завдань для користувача.
